# CS-320 Software Test Automation and Quality Assurance

## Course Overview

In CS-320, I developed Java applications and used JUnit testing to verify that software met specific requirements. Throughout this course, I gained experience in unit testing, validating user input, identifying potential defects, and improving software reliability. This repository contains my Contact Service files from Project One and my Summary and Reflections Report from Project Two.

## How can I ensure that my code, program, or software is functional and secure?

I can ensure that my software is functional and secure by carefully reviewing requirements, writing comprehensive unit tests, and validating both acceptable and unacceptable inputs. During this course, I used JUnit to test the Contact, Task, and Appointment services. These tests helped verify that the programs handled data correctly and rejected invalid information. I also learned the importance of reviewing code and making improvements based on testing results and instructor feedback. For example, I added additional validation, improved tests to verify stored objects, and implemented defensive copying to protect appointment dates from unintended changes. These experiences reinforced the importance of continuous testing, secure coding practices, and maintaining reliable software.

## How do I interpret user needs and incorporate them into a program?

I interpret user needs by reviewing the project requirements and identifying the specific functions the software must perform. I then translate those requirements into programming rules and test cases to verify that the software behaves as expected. For example, the Contact Service project required contact IDs, names, phone numbers, and addresses to follow specific length and formatting restrictions. I incorporated these requirements into my Java classes and created JUnit tests to verify that the restrictions were enforced. This process helped me understand how user requirements influence software development and testing.

## How do I approach designing software?

My approach to software design begins with understanding the problem and breaking it into smaller, manageable components. I identify the required functionality, determine how the classes should interact, and develop the program in stages. In CS-320, I used separate classes for data objects and service operations, which made the programs easier to organize, test, and maintain. I also learned that software development is an iterative process. Testing, reviewing results, and making corrections are essential parts of producing reliable software. Moving forward, I plan to continue using modular design, automated testing, and regular code reviews to improve the quality of my software projects.
